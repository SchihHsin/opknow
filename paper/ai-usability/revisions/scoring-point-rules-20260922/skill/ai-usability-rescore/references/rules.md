# 单一得分评分规则 v1

版本：`point-rubric-20260922-v1` · 2026-09-22

本版用于对同一批已保存的实验记录重新评价。采集协议、任务、模型和检索预算不变；本文件不启动重新采集，也不覆盖旧评分。基准为实验提交`87e04c16e913da3f614d85f9f8ab3ad36cde0af5`的冻结规则，而不是当前安装Skill的默认规则。

**所有M1–M10统一采用单一得分或明确的不可评分状态。** 不输出分数上下界，不取旧区间中点、下限、上限或candidate_score代替裁决。M11按确定输入计算；它是综合指数，不是正确概率。单一得分是本量规下的判定，不意味着测量没有误差。

## 一、统一判定与状态

每份记录按以下顺序处理：

1. 核对run_id、原始过程哈希和回答阶段。来源、检索前回答、最终答案分别使用，不得互相替代。
2. 按原题及冻结任务包确定适用范围。评价者先列出所需内容、主路线、必要配套关系与关键说法，再评分；不能看过分数后增删要求。
3. 确认记录能否识别待评价对象，包括来源归属、返回类型和陈述含义。无法识别时先复核，不能直接选低档。
4. 对保存的材料逐项检查。区分“已检查并发现缺项/矛盾”与“评价者没有核查依据”。
5. 依据本指标的明确条件给单分；若现有事实的不同解释仍会改变分档，则保留待复核，不猜分。低分也必须有证据。

| status | score | 含义 |
| --- | --- | --- |
| `scored` | 数值 | 已满足该档判定条件 |
| `needs_review` | null | 尚有可裁决的归属、相关性、技术含义或分档争议 |
| `unscorable` | null | 已完成必要复核，但保存记录不足以给出分数；必须列缺失事实 |
| `blocked` | null | 指标的上游评价对象没有取得，例如M3没有正文可评 |
| `not_applicable` | null | 任务预先不要求该项，或按该指标明确规定不适用 |
| `not_assessed` | null | 还未执行评价，不能混成证据不足 |

**证据状态与得分独立。** 另存引用位置、支持/反驳/未核验事实、完整性核验及执行验证状态。证据记录可保留争议项，不能再生成评分区间。不同事实候选若均落在同一档，可以输出该档，并说明不影响评分的争议；若会跨档，则必须先裁决或保留null。

M1、M3–M10为1–5整数；M2先逐文档给1–5整数，再等权平均，因此可为确定小数。M11为0–100连续数。展示舍入不改变原始计算精度。

## 二、逐项规则

### M1 官方可发现性

保留首次官方命中的查询轮次与排名五档：

| 分数 | 判定条件 |
| --- | --- |
| 1 | 规定搜索预算已完成，必要结果列表完整，仍未发现相关官方来源 |
| 2 | 第3次或之后查询才首次发现相关官方来源 |
| 3 | 第2次查询首次发现相关官方来源 |
| 4 | 第1次查询第2–5位出现相关官方来源 |
| 5 | 第1次查询第1位为相关官方来源 |

本批最多4次查询，每轮仅以前5位判定命中，完整返回仍全部保留。第1轮第6位不算该轮评分命中，后续仍按前5位检查。先确认命中条目的官方身份、与原题的相关性，再按保存的有序列表计算。不能用最终答案引用顺序代替搜索排名；继续检索不降低已经确定的首次命中分数。前序查询失败/结果丢失、身份或相关性争议可能改变档位时记needs_review；复核仍不可确定则unscorable。没有耗尽预算且未命中，不得给1分。不能仅因精确排名有疑问就输出区间：若所有可能排名均在首次第2–5位，仍为4分。

### M2 官方可抓取性

评价对象仍是目标官方文档的实际返回表示及可观察缺损，不改成任务内容完整性；后者由M3评价。

| 分数 | 新版判定条件 |
| --- | --- |
| 1 | 请求失败、拒绝访问、错误页、无返回，未取得可识别的目标内容 |
| 2 | 取得目标标题、导航或元数据，但没有可识别正文 |
| 3 | 只取得明确摘要/摘录，未取得直接正文 |
| 4 | 取得直接正文，但存在明确截断、缺页或可核对的目标边界缺失 |
| 5 | 取得直接正文，记录及允许使用的既有核验材料中未观察到上述缺损 |

判定顺序：**目标匹配与归属 → 返回表示 → 是否有缺损证据**。错误的页面不因文字多而算目标正文；摘要含代码仍为3。无法区分正文与工具改写摘要时不能因“没有截断提示”给5，须先复核。原文没有覆盖任务某一步，不自动算抓取缺页，可能是M3的内容缺口。

本版5分不再表示“已证明全文完整”。这是相对旧规则的实质变化：旧规则因完整性unknown给4–5，新版将可观察获取状态与独立完整性核验分开。必须另存`completeness_verification`：`confirmed_complete` / `confirmed_incomplete` / `not_independently_verified`及依据。工具自称完整不足以设confirmed_complete；有独立缺页证据时不能给5。不得从未观察到缺损推导网站完整送达率。

覆盖全部实际fetch返回的来源清单。按同一请求URL去fragment合并重试；同文档沿用最后一次实际派发返回作为评分状态，早期障碍另存，不挑最好一次。未知镜像、重定向不得擅自合并。每个独立官方文档确定分数后由程序等权平均；不得删掉可能属于官方但归属未定的文档求均值。存在影响纳入的身份疑点或无法定分文档时，M2整体needs_review/unscorable。没有官方目标文档可评时记blocked，不凭空补一个1分。

### M3 官方正文详尽度

沿用原五档，以原题所需内容为范围：

1. 已取得正文只有概述，没有相关解释或操作细节。
2. 有零散参数、片段或说明，但未形成完整解释或操作段落。
3. 有完整段落，但完成原题所需关键步骤、参数或约束仍缺。
4. 主流程、参数与前提已说明；仅原题明确涉及的分支、约束或参考细节未齐。
5. 原题所需解释、步骤、参数与约束均已说明，无需另外补齐这些内容。

先列任务要求并区分主流程与题目明确涉及的补充内容；缺口必须对应所检查正文的位置或覆盖清单。按已满足的最高档判定，不能因“也可能更详细”给区间。没有取得正文记blocked；正文存在但评分者尚未检查完记needs_review。记录充分显示本次取得内容缺项，可以评分，但不能写成官网不存在相关内容。版本选择归M4；已发现的技术错误另存，不以长度替代详尽度。

### M4 版本清晰度

沿用原五档，改为明确分支判断：

1. 已取得可评官方资料，但没有任务所需版本信息。
2. 有版本信息但无选择依据，或必要适用关系存在未消解的官方冲突。
3. 部分适用关系明确，但仍缺完成版本选择所需关系。
4. 所有必要关系有依据，需自行合并官方约束才能确定版本。
5. 所有必要关系由官方直接表格或规则明确，直接查表/套用即可确定。

先查未消解冲突，再查必要关系是否缺失，最后区分combined/direct。缺关系不能4/5；直接规则只覆盖部分组件也不能5。无正文可评为blocked；无需版本选择为not_applicable。可选版本是单值或范围均可，不按版本或页面数量扣分。合并需展示每条约束及推导，不能把共享某个CUDA版本当成任意两组件兼容的证据。真实判定争议用needs_review，不输出3–4或4–5。

### M5 二手丰富度

沿用预算内实际发现、去重后的相关独立第三方来源数n：

| n | 分数 |
| --- | --- |
| 0 | 1 |
| 1–2 | 2 |
| 3–4 | 3 |
| 5 | 4 |
| ≥6 | 5 |

先完成来源归属、相关性、独立性清单，再程序映射。相关性须说明该条目如何对应原题的工具、操作、约束或解释需求，不能仅凭生态关键词。正文取得不是计数前提，清晰的标题/摘要可提供判断依据。官方发布者、官方仓库不计第三方；同一第三方内容的原文、转载与镜像合并计一次，不因只发现转载就计零；无法核清内容归属时保留争议。官方内容镜像仍按官方渠道分类。

**数量不确定不必等于得分不确定。** 确定3条、最多4条都为3分；确定至少6条时额外疑项不影响5分。保留疑项清单，不伪造准确来源数。有4条确定、另1条疑项则会跨3/4档，先复核；不能一概排除疑项给低档，也不能一概计入给高档。

共同预算是采集上限，M5记录有效运行实际发现的数量，不要求事后补齐未用预算。另报实际查询数、停止原因与预算使用程度。0仅表示该运行未发现相关独立第三方，不能直接推断整个生态无第三方，也不自动授权M11将第三方渠道置0。必要搜索结果列表丢失、计数对象无法核对时needs_review/unscorable。

### M6 二手可信度／一致性

评价本次已取得的、会改变操作/解释/版本判断的可识别关键说法及其支持情况。清楚的搜索摘要陈述可评，不要求每条都抓到全文；仅标题或无法确定含义的碎片不构成完整可评说法。

先列关键说法与核对依据；2–5档共同前提是完成固定证据包内全部可识别关键说法的规定检查，再按以下优先顺序判定：

1. 存在与可靠依据直接矛盾、尚未解决的关键说法。
2. 已取得可识别关键说法并完成规定核对，但没有可追溯的核对依据支持它们，且无已确证关键矛盾。
3. 部分关键说法有可追溯支持，其余经规定检查仍无足够支持，且无未消解关键矛盾。
4. 全部关键说法有可追溯支持，无未消解矛盾，但缺少独立来源交叉印证。
5. 全部关键说法有可追溯支持及独立来源交叉印证，无未消解矛盾。

“全部”限定于本次可见、预先列明的关键说法，不包括未取得页面中想象的内容。已发现关键矛盾优先判1，不能用更多一致条目将其平均掉。转载不算独立互证；旧文只有与当前适用事实相冲突才构成反证。

2/3分表示观察到的核验支持程度，**不表示未核验说法为假**。尚未完成规定核对不能直接给2或3；只取得无法识别说法的碎片、完整来源清单缺失，或核对依据的可靠性/适用性尚有争议时needs_review/unscorable。确认没有第三方材料时才记not_applicable；有第三方候选但可评说法不足不等于N/A。

核对仅使用固定的保存证据包及已归档参照；列出实际检查材料、未核验说法及检查边界，不按来源平台名猜可信度。禁止“以后取得全文可能提高分数”形成当前区间；也禁止把“没有抓第三方全文”一律判低分或不可评分。

### M7 模型自带知识（无检索回答表现）

保留指标名称与五档，明确它不测训练数据密度。只评价首次工具调用前保存的回答，经事后核查其正确性与覆盖：

1. 没有可核验正确任务知识，或任务关键主张被可靠证据否定。
2. 只有正确概念，没有具体正确方法或解释。
3. 有正确方法/解释片段，但关键流程或解释环节仍缺。
4. 正确完整主流程/解释已经给出，原题涉及的具体参数或约束仍需补充。
5. 原题所需流程、解释、参数与约束已准确覆盖。

先列原题要求和先验陈述，分别记录已支持、已反驳、实际未给出、评价尚未核清。任务关键错误与非关键细节分别说明；不能将已知错误改称“缺少信心”或只机械降一级。某低档成立必须有该档要求的正面证据，不能把核验未知当成模型知识缺失。真实正确性争议若可能改变档位则needs_review，无法补齐依据则unscorable。

自报不确定不扣分，自报高信心不加分。不从最终答案反推先验，不用检索后补出的内容提高先验分数；但可用归档来源作为核验依据。模型回答已达到某档且没有改变该档的未决事实时给单分，不再给相邻区间。检索前回答丢失时不可评分。

### M8 检索成本

不改变定义：C=S+F，按实际派发事件计数，失败也计一次，拦截后未派发的请求不计。

| C | 分数 |
| --- | --- |
| ≥9 | 1 |
| 7–8 | 2 |
| 5–6 | 3 |
| 3–4 | 4 |
| 1–2 | 5 |

计数和档位由程序完成。C=0、过程异常中断或派发日志不完整时不能奖励5分，先核查运行有效性。调用成本与是否答好分开；不能把较少调用解释为更高答案质量。保留耗时等观测，不改本次计算权重。

### M9 版本可锁定性

按原题需要的组件和实际采用路线，仅评价最终答案中的定版及依据：

1. 没有给出原题需要的版本信息。
2. 有版本但没有有依据的适用版本/范围，或关键定版与证据矛盾。
3. 部分所需组件有版本依据，其余没有确定。
4. 所有所需组件有依据的适用范围，但至少一项未锁定具体版本。
5. 所有所需组件均有依据的具体版本，无未消解配套冲突。

先查关键矛盾与依据，再查覆盖所有必要组件与锁定粒度。范围答案可以技术正确，但不因此改成5分；不能为了5分臆定本机版本。所需组件按任务包确定，I/E等不因本机版本未知就自动N/A。没有版本要求时N/A。答案实际缺项可按对应低档评分，评分者未核清依据则待复核，不能靠“3或4都像”给区间。

### M10 操作可执行性

沿用原五档，按最终答案主路线的补改需要判断：

1. 只有目标描述或示意，没有具体可执行方案。
2. 只有操作骨架，关键操作无法根据答案确定。
3. 有具体方案，但存在需要修正的内容错误或需要补写的步骤、代码、参数说明。
4. 指导完整，只需替换已明确标识且解释含义的用户环境值，例如模型路径、设备号。
5. 指导和适用前提明确，无需补写、修正或替换这些环境值即可执行。

先判断方案是否存在及是否只是骨架，再检查内容补改，最后区分仅环境替换与无需替换。4/5之间必须列出需替换字段；有内容错误不能4/5。3分须指出明确补改处，2分须指出关键操作不可确定的原因。主路线含不可核查的外部API/兼容性断言、可能改变补改判断时needs_review，而非假定错误给3或给3–5。

仅未实际运行不是扣分理由。另存执行状态：实际通过、实际失败、仅内容检查或未验证；内容评分5不表示硬件复现成功。明确标注未知也不豁免任务实际要求的关键步骤。纯概念题按冻结适用性N/A。每项有最终答案逐字引文及补改清单，不从来源正文的详尽度替代最终答案评分。

### M11 综合置信度

保留公式、百分制、0.30/0.10系数及分项关系：

`xi=Mi/5; OFF=x1*x2*x3; SEC=x5*x6; OWN=x7`

`M11=100*[1-(1-OFF)*(1-SEC)*(1-OWN)]*(0.7+0.3*x4)*(0.9+0.1*x8)`

M9/M10独立报告，不进入公式。展示一位小数，计算保留原始精度，不重新拟合系数。

**本版输入策略：** 所有实际参与渠道的所需分项均为有效单值后才计算。M2均值小数是有效单值。所需项needs_review→M11 needs_review；尚未完成评价→not_assessed；已确认必要输入无法评分→unscorable，并列missing_inputs。不输出综合区间，不用满分渠道抵消其他未知输入来绕过复核，也不因希望有总分而补齐分项。

仅在归档证据确认本轮整条渠道没有可用支撑时，沿用原`confirmed_unavailable`约定将该渠道贡献置0，并豁免该渠道不存在的下游分项；须保留归属与理由的独立核验。M5=1、M6=N/A、单页失败不能自动推出渠道为0；完整预算内没有相关第三方来源才可作为原约定下无支撑依据。M4任务不适用时版本因子为1，M4仍N/A；M8不可用不能中性处理。

相对于旧版，取消区间传播并收紧点值的输入前提属于报告/计算规则变化，可能使一部分旧点值暂不可算。不得把“计算出来”作为证据充分或规则有效的证明。

## 三、重评约束

- 对全部156次既有有效运行按同一新规则重新评价，不能只重评区间格。G的6格继续单列，25对CANN/CUDA仍为主比较。
- 本次规则修订不重新采集。将保存的原始材料与既有核验参照组成固定证据包；后续若另查资料，须新记为评价参照，不能写回模型当时的上下文或检索成本，本次不自动启动新检索。
