# 旅程时序图

将一段真实或规划中的任务过程表现为「时间向下、参与者横向分列」的可读旅程图。适用于人机协作、Agent 工作流、服务流程、开发者任务和带检索/执行/决策的端到端过程。优先按用户指定的产物实现；若没有指定，HTML + SVG 适合带悬浮详情、筛选或自主度切换的图。

## 建模

先从材料中整理参与者、事件顺序、信息流、决策、阶段、旁路和证据，再绘图。不要把图的视觉顺序误当成已验证事实：将实测、来源明确的内容与重建/推演步骤区分开，并在图注或详情中标明边界。

用稳定 ID 和结构化数据驱动绘制，而非逐项手写 SVG：

- 参与者：`id / label / color`，按交互关系从左到右排列。
- 事件：`id / kind / title / actor / phase / detail`，按时间顺序排列；可选 `blocked`、证据或指标映射。
- 消息：`from / to`，绑定事件；决策事件落在决策者泳道，不必伪造一条消息。若流程会回退，另建回退关系并连回触发点；不要把循环伪装成直线步骤。
- 阶段：事件起止索引和简短名称。分支单独描述起点、目标参与者与说明。
- 若角色随模式变化，用语义角色（例如 `executor`）并在渲染时解析到当前参与者；不要复制整份事件数据。

## 视觉语法

- 纵向时间轴：参与者列头在顶部，每条生命线为浅灰竖线；事件等距自上而下排列。给长标题动态留高或换行，避免相邻标签碰撞。
- 每个跨参与者事件画一条水平箭头。箭头起点代表发起方，终点代表接收方；发起方生命线上放带事件 ID 的小圆标，标题居中放在箭头上方。自身动作不画无意义的跨列箭头，改为在该泳道放圆标并把标题放侧边。
- 角色色用于列头、事件标记和少量强调；普通生命线保持中性。可沿用参考页的颜色起点：AI 紫 `#6B5BA8`，人类用户蓝 `#2F3D63`，本机工具青绿 `#3F7D72`，官方来源红 `#C8102E`，社区来源赭金 `#BA7517`。若项目已有颜色语义，优先沿用。
- 跨泳道消息统一在发起方线上放白底、角色色描边的小圆标，圆内写事件 ID；这样方向与发起者一眼可辨。独立于消息的本地动作可用圆角矩形；决策使用决策者泳道上的窄竖向圆角条。决策条可用深金实底表示「必须由人裁定」，浅金斜纹表示「路线/技术选择」；若任务分类不同，应改成图例中能解释的语义。
- 受阻要同时表达「请求」与「失败结果」：请求箭头用红色，失败返回在下一小行用红色虚线反向箭头，并写明失败结果和 `✕`。阻塞事件标记再加红色外环。不要只靠红色表示失败。
- 用户绕过 AI 或主路径的独立求证/升级路径用另一种深蓝虚线，目标仍指向具体参与者；图例说明它不经过主协作者。
- 左侧可加阶段色带和主导方色带：阶段带按事件索引分块、使用低饱和浅底；主导方带显示当前阶段由谁主导。阶段块也可放精简的 AI/人动作数、比例条或检索/产出/执行/决策维度提示；这些统计从当前事件数据推导，不要另手工维护一套数值。辅助带不能压缩参与者列或遮盖消息。
- 必须提供图例解释参与者、箭头、虚线、决策样式、受阻标记和阶段/主导方色带。颜色同时配合线型、形状或文字，保证缩放和灰阶下仍可读。

## 可选交互

当来源材料确实提供了节点细节时，节点悬浮展示简短摘要，点击固定完整详情；阶段和泳道可展示阶段边界、职责或统计。详情应保留来源和不确定性，不要为了填满提示框而编造信息。

若要比较不同自主度或流程模式，添加离散档位控件。将事件执行者、决策者、消息端点和可见旁路从同一档位状态推导；每次切档完整重绘并同步阶段统计、主导方带、交接次数和图例说明。事实内容（例如某来源确实抓取失败）不随档位改写。提供静态图例和当前模式说明，确保不操作控件也能看懂初始图。

## HTML / SVG 实现提示

用 SVG `viewBox` 和数据坐标生成泳道与事件；箭头 marker、决策纹理等定义放在 `<defs>`。按参与者数量计算列间距，按事件数量计算画布高度；不要为了塞进窄屏而挤扁列。将 SVG 放入 `overflow-x:auto` 的容器，小屏保留横向滚动。重绘交互状态前清理旧图元并重建 defs，避免重复 marker ID 或残留节点。标题与详情文本按内容换行，长图仍能逐段浏览。

## 交付前检查

确认时间顺序清楚、每条消息方向正确、决策落在合适的角色上、受阻有可见返回、分支能追溯到起点、阶段范围覆盖正确。检查长标签、相邻节点、最左辅助带和最右泳道在目标视口中没有裁切；悬浮/点击说明与图例一致。对于推演内容，明确标注假设，避免把示意图包装成实测记录。
